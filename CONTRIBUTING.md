# Contributing to Inti.js

Thanks for your interest in contributing! Inti.js is MIT-licensed open source, and we welcome pull requests from anyone.

By taking part you agree to follow the [code of conduct](CODE_OF_CONDUCT.md).

## Getting Started

```bash
git clone https://github.com/intijs/inti.git
cd inti
npm install
npm run build
npm test
```

The monorepo uses npm workspaces. All packages live in `packages/` and apps in `apps/`. It needs Node 22 and [Bun](https://bun.sh), which runs the tests.

## Development

- **Build everything**: `npm run build`, in dependency order
- **Run tests**: `npm test`
- **Dev server**: `npm run dev` (starts the demo site)

These run a real project end to end, and they are slower:

| Command | What it checks | Needs |
|---|---|---|
| `node scripts/astro-compat.mjs <5\|6\|7>` | The documented setup on each Astro major | |
| `node scripts/create-inti-check.mjs` | Projects generated by `create-inti` | |
| `npm run test:genui` | Generation and personalization | |
| `npm run test:cloudflare` | The Cloudflare package in `workerd` | |
| `npm run test:wordpress` | A real WordPress, destroyed afterwards | Docker |
| `npm run test:kitsuden` | A disposable Kitsuden, destroyed afterwards | Docker and a Kitsuden image |

## Pull Requests

1. Fork the repo and create your branch from `main`.
2. If you've added code, add tests.
3. Make sure all tests pass (`npm test`).
4. Write a clear PR description explaining what changed and why; the [pull request template](.github/pull_request_template.md) lists the checks.

## Code Style

- TypeScript strict mode.
- No comments unless the *why* is non-obvious.
- Prefer editing existing files over creating new ones.
- No backwards-compatibility shims — just change the code.

## Releasing

Build first with `npm run build`, then publish in dependency order. npm needs the `intijs` organization and two-factor authentication.

1. `@intijs/core`
2. `@intijs/genui`
3. `@intijs/cloudflare`, every `@intijs/adapter-*`, `@intijs/cli`, `@intijs/mcp`
4. `create-inti`, last, because it installs the others

```bash
npm publish -w @intijs/core
```

## Reporting Issues

For a vulnerability, see [SECURITY.md](SECURITY.md) instead. Otherwise use [GitHub Issues](https://github.com/intijs/inti/issues). Include:
- Inti.js version
- Astro version
- CMS adapter and version
- Steps to reproduce
